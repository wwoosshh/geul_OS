# 페이즈 4 — 저장과 영속

**기간**: 약 3~6개월 (12~20주)
**핵심 작업**: 디스크 드라이버 + 파일시스템 + SIP 상태 영속 체크포인트
**다른 페이즈와의 관계**: 페이즈 3의 SIP 모델 위에서 동작. 페이즈 5의 자체호스팅이 이 페이즈의 파일 I/O에 의존.

이 문서는 페이즈 3 통과 후 다시 상세화한다. 지금은 윤곽만.

## 통과 조건

1. **디스크 I/O**: 글 OS가 가상 디스크에 임의 블록 읽기/쓰기 가능
2. **파일시스템**: 파일 생성/읽기/쓰기/삭제, 폴더 계층 동작
3. **영속 체크포인트**: 임의 SIP가 30초 간격으로 자동 저장됨
4. **재부팅 후 재개**: 시스템 재부팅 후 마지막 체크포인트 상태에서 SIP들이 자동 재개
5. **체크포인트 비용**: 100MB SIP의 체크포인트가 1초 미만 (결정 D의 spike 기준)

## spike (2~3주)

### spike-1: 디스크 드라이버 범위 (1주)
- ATA/AHCI vs virtio-blk (QEMU 친화)
- 가장 단순: virtio-blk + QEMU 환경에서 시작, 실기는 후순위

### spike-2: 파일시스템 선택 ★ 보류 결정 확정 시점
- 자체 FS 설계 vs FAT32 호환
- 작품성: 자체 (구조도 한국어 자료구조로)
- 실용성: FAT32 (호스트와 파일 교환 가능)
- **권장**: 자체 FS. 호스트 파일 교환은 페이즈 5에 별도 직렬화 도구로

### spike-3: 영속 체크포인트 비용 측정
- 결정 D의 핵심 검증
- 100MB SIP를 만들어서 측정. 비용이 폭발하면 결정 D 폴백 (R-11)

## 본 작업 (윤곽)

### 디스크 드라이버
- virtio-blk (QEMU) 우선
- 후기에 AHCI/NVMe 검토 (실기 부팅 시 필요)

### 파일시스템 (자체 또는 FAT32)
- 슈퍼블록, inode 등가물(파일고유번호), 데이터 블록
- 폴더는 파일의 특수형
- 일관성: 저널링 또는 copy-on-write

### 영속 체크포인트
- SIP 상태 = 메모리 영역 + 레지스터 + 능력 목록
- 점진적 체크포인트 (dirty page 추적 — MMU dirty bit 또는 SW write barrier)
- 디스크 비동기 쓰기

### 재부팅 후 재개
- 부팅 시 체크포인트 영역 스캔
- SIP 메모리 복원
- 스케줄러에 SIP 재등록

## 위험과 폴백

### R-11: 체크포인트 비용 폭발
- spike에서 발견 시 결정 D 폴백 → 명시적 저장 모델
- 작품성 손실. 그러나 결정 A·B 살아 있으면 정체성 유지

### R-12: 디스크 드라이버 복잡도
- ACHI 사양이 두꺼움. virtio-blk으로 우회

### FS 일관성 깨짐 (부팅 중 정전 등)
- 저널링 또는 CoW 둘 중 하나 필수
- 폴백: fsck 등가물 (수동 복구)
