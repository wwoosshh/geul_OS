**기간**: 약 3~6개월 (12~20주)
**핵심 작업**: 다중 SIP 시간 분할 실행 + 동기 메시지 IPC + 능력 토큰 시스템
**다른 페이즈와의 관계**: 페이즈 2의 격리 모델 위에서 실행 환경 완성. 페이즈 4의 영속 모델이 이 페이즈의 SIP 모델에 의존.

## 통과 조건

1. **다중 SIP 라운드로빈 스케줄**: 3개 이상 SIP가 시간 분할 실행, 시리얼 로그로 확인
2. **선점 스케줄**: 타이머 IRQ가 현재 SIP를 중단하고 다른 SIP로 전환
3. **메시지 IPC**: SIP A가 보낸 메시지를 SIP B가 받음, 응답 메시지 가능
4. **IPC 성능**: 두 SIP 간 핑퐁이 단일 코어에서 1만 회/초 이상
5. **능력 발급/검사**: framekernel이 SIP에 파일 접근 능력 발급, 무능력 SIP는 거부됨
6. **능력 위임**: SIP A가 가진 능력 일부를 SIP B에 위임 가능
7. **무한 루프 SIP가 시스템을 멈추지 않음** (선점 동작)

## spike (2~3주)

### spike-1: 메시지 형식과 채널 설계 (1주)

- 메시지는 어떤 자료구조? (헤더 + 페이로드?)
- 단일 주소공간이므로 페이로드 = 포인터 + 능력?
- 채널(통로)이 명시적 객체인가, 묵시적인가?

### spike-2: 능력 토큰 표현 (1주)

- 토큰은 어떤 타입? 64비트 정수? 글 구조체?
- 위조 방지: 컴파일러가 보장 (글 1급 타입이라면) vs 런타임 검증
- 위임 가능성: 능력 자체에 권한 비트?

### spike-3: 스케줄 모델 (1주)

- 협력적 vs 선점적
- 단일 큐 vs 우선순위 큐
- SIP 상태 머신: 실행 / 대기(메시지 기다림) / 멈춤(능력 없음 등)
