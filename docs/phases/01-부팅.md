# 페이즈 1 — 부팅과 콘솔

**기간**: 약 3개월 (10~13주)
**핵심 작업**: long mode 진입 + 화면 출력 + 키보드 입력
**다른 페이즈와의 관계**: 페이즈 0의 컴파일러 OS 모드가 전제. 페이즈 2의 인터럽트·페이지 작업이 여기서 익힌 저수준 기법 활용.

---

## 진입 조건

- [ ] 페이즈 0 통과 (글 한 줄 커널이 QEMU에서 부팅, 정지점 도달)
- [ ] `--freestanding`, Multiboot2 ELF, 인라인 asm/인트린식, 섹션 속성 모두 동작
- [ ] 빌드 → QEMU 사이클 10초 이하
- [ ] 페이즈 0 spike(VGA 출력 데모)에서 한 글자라도 화면에 찍어 봄

---

## 통과 조건

1. **부팅 메시지**: 부팅 시 "안녕하세요, 글 OS" 가 화면에 자동 출력
2. **키 입력 에코**: ASCII 키를 누르면 화면에 표시 (백스페이스 동작)
3. **한글 출력**: VGA 텍스트 모드의 한계 안에서 (CP949 폰트 또는 비트맵) 한글 일부 출력 가능
4. **인터럽트 동작**: 키 입력이 폴링이 아니라 IRQ 1 (PS/2 keyboard) 처리로 동작
5. **타이머 동작**: PIT 또는 APIC 타이머가 1초 간격으로 카운터 증가 (시리얼 로그로 확인)
6. **트리플 폴트 없음**: QEMU `-no-reboot` 옵션 없어도 안 죽는 안정 상태

---

## spike (1~2주)

**핵심 질문**: long mode 전환과 IDT 설정의 글 코드 표현이 가독성 있게 가능한가?

- 구조체(묶음) 비트 필드 표현이 IDT 엔트리(64비트 안에 다양한 비트 필드)에 맞는가?
- 페이지 테이블 엔트리도 같은 문제 — spike에서 1~2개 엔트리 글 코드로 표현해 보고 가독성 검증

### spike 결과
- 묶음 비트 필드가 부족하면 → 비트 연산 헬퍼 함수로 우회 (가독성 손실)
- 정말 어려우면 페이즈 0의 컴파일러 변경에 비트 필드 지원 추가 (페이즈 0으로 복귀)

## 본 작업

### W1 — 부팅 흐름 설계

- [ ] long mode 전환 시퀀스 정리: GRUB → 32비트 보호모드 → 페이징 켜기 → 64비트
- [ ] GDT 최소 셋업 (커널 코드, 커널 데이터, TSS — 단순)
- [ ] 임시 항등 매핑 페이지 테이블 (글 OS 가상 주소 = 물리 주소 첫 4MB)

### W2~W3 — 32→64비트 전환

- [ ] 32비트 보호모드 진입 코드 (GRUB 멀티부트2 후 시작 지점은 32비트)
- [ ] 4단계 페이지 테이블 임시 작성 (PML4 → PDPT → PD → PT)
- [ ] CR3 설정 + CR4.PAE + EFER.LME + CR0.PG 순서대로
- [ ] long mode 진입 후 64비트 코드 jump
- [ ] **첫 64비트 명령에 도달 확인** (GDB로)

### W4 — VGA 텍스트 출력

- [ ] 0xB8000 에 직접 쓰기로 한 글자 출력
- [ ] `[문자 글자를 위치에 화면쓰기]` 같은 글 함수
- [ ] 줄바꿈·커서 위치·스크롤 처리
- [ ] "안녕하세요, 글 OS" 출력 ⇒ 통과 조건 1번

### W5 — 시리얼 디버그 출력

- [ ] COM1 (0x3F8) 초기화
- [ ] 한 글자 출력 → 문자열 출력 → 정수 16진수 출력
- [ ] `[메시지를 시리얼로그]` 같은 디버그 함수
- [ ] QEMU `-serial stdio` 와 결합하여 호스트 콘솔에 로그

### W6~W7 — IDT 설정과 첫 예외 처리

- [ ] IDT 엔트리 구조체 (글 묶음)
- [ ] 256개 엔트리 초기화, 처음에는 모두 default panic 핸들러
- [ ] `lidt` 인트린식 호출
- [ ] 의도적 divide-by-zero 트리거 → 0번 예외 핸들러가 시리얼에 "예외 0" 로그
- [ ] 비트 필드 정확성 검증 (R-07)

### W8 — PIC 또는 APIC 초기화

- [ ] 8259 PIC 마스킹 (모든 IRQ 차단)
- [ ] 또는 APIC 모드로 진입 (더 깔끔하지만 복잡)
- [ ] **결정**: 페이즈 1은 PIC, 페이즈 3에서 APIC로 전환 검토

### W9 — 타이머 IRQ

- [ ] PIT 모드 3 (square wave, 100Hz)
- [ ] IRQ 0 핸들러: 카운터 증가 + EOI
- [ ] 1초마다 시리얼 로그 ⇒ 통과 조건 5번

### W10 — PS/2 키보드 IRQ

- [ ] IRQ 1 핸들러
- [ ] 스캔코드 → ASCII 변환 표 (US 키보드 기준; 한글은 페이즈 1 범위 밖)
- [ ] 키 입력 화면 에코 ⇒ 통과 조건 2번
- [ ] 백스페이스 처리

### W11 — 한글 출력 첫 시도

- [ ] VGA 텍스트 모드는 1바이트/글자, 한글은 2바이트 필요 → 한계 있음
- [ ] **결정**: VGA 텍스트로 영문만 가능, 한글은 페이즈 3에서 프레임버퍼로 / 또는 페이즈 1에서 CP949 폰트 활용
- [ ] 작품성 위해 1차 시도: VGA 9th-line 폰트 영역에 한글 비트맵 박기 (제약 있음)
- [ ] 통과 조건 3번 ⇒ 부분 통과로 정의 가능

### W12 — 안정화

- [ ] 트리플 폴트 없이 1시간 이상 키 입력 받기
- [ ] QEMU `-no-reboot` 옵션 없이도 안정 (통과 조건 6번)
- [ ] 모든 예외 핸들러가 panic이 아니라 로그 + 안전 정지

### W13 — 회고 + 페이즈 2 spike 시작

- [ ] 회고
- [ ] 페이즈 2 spike 시작 (R-03 — 컴파일러 격리 검증): 글 컴파일러가 막을 수 있는 위반 종류 카탈로그

## 위험과 폴백

### R-06: long mode 전환 버그
- W2~W3에서 막힘 가능성 가장 높음. trip fault 무한 재부팅
- **대응**: Bochs로 명령 단위 추적, `magic_break` 활용. Intel SDM Vol 3 Chapter 9 재독
- 폴백 없음. 정확히 풀어야 함

### R-07: 인터럽트 디스크립터 비트 필드 실수
- spike에서 글 묶음으로 표현 가능 검증 후 진행. 그래도 실수 가능
- **대응**: 비트 단위 출력으로 IDT entry 16바이트를 hex dump로 검증

### 한글 출력 제약 (W11)
- VGA 텍스트의 1바이트/글자 한계는 본질적 — 통과 조건 3번을 페이즈 3로 이관 가능
- **이관 결정 시 결정 기록에 한 줄**

---

## 결정해야 할 것

1. **PIC vs APIC**: 페이즈 1은 PIC 권장 (단순). APIC는 페이즈 3
2. **한글 출력 방식**: VGA 텍스트 제약 안에서 / 프레임버퍼로 이관
3. **panic 정책**: 모든 예외에서 정지 / 일부는 무시 가능 — 디버그 시 어떻게 멈출지
