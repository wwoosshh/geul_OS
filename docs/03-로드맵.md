# 마스터 로드맵

이 문서는 **6개월 뒤·1년 뒤·2년 뒤 당신이 펼쳐 보는 지도**다. 길을 잃지 않는 것이 이 문서의 단 하나 목표.

---

## 0. 어떻게 이 문서를 쓰는가 (메타)

### 0-1. 페이즈 구조

각 페이즈는 다음 5요소를 가진다:

1. **진입 조건** — 이전 페이즈가 무엇을 만족해야 시작 가능한가
2. **통과 조건** — 객관적으로 측정 가능한 끝 조건
3. **spike** — 1~2주 시간박스로 핵심 가정 검증
4. **본 작업** — 통과 조건을 만족시키는 작업들 (코드 아님, 계획)
5. **폴백** — spike나 본 작업에서 막힐 때의 대안 경로

### 0-2. 막혔을 때의 절차 (★ 중요)

길을 잃을 위험이 가장 높은 순간 = "이 작업이 안 됩니다"가 발견되는 순간. 그때 다음을 차례로 한다:

1. **현재 페이즈의 폴백 절을 본다** (`docs/phases/<N>-*.md`)
2. **위험 등록부를 본다** (`docs/04-위험과대응.md`)
3. **아키텍처 비전의 폴백을 본다** (`docs/02-아키텍처비전.md`의 "폐기 시 폴백")
4. 그래도 답이 없으면 **현재 페이즈를 중단**하고 결정 기록(아래 §4)에 사실을 적은 뒤 spike 시간을 다시 잡는다

**중요**: "그냥 다른 거 해보자"로 옮겨가지 말 것. 폴백은 명시적으로 선언하고 기록한다.

### 0-3. 진행 상태 추적

- 매주 금요일: 현재 페이즈 문서 끝의 "진행 일지"에 한 단락
- 페이즈 종료 시: 회고 한 페이지를 같은 파일 끝에 추가
- 큰 결정 시: §4 "결정 기록" 에 한 줄

## 1. 6단계 개요

```
페이즈 0 ─ 준비       (3개월)   컴파일러 OS 모드 + 환경 셋업
   │
페이즈 1 ─ 부팅       (3개월)   부팅 + 화면 + 키보드
   │
페이즈 2 ─ 격리       (4~6개월) 메모리 + 인터럽트 + 첫 SIP (★ 핵심 검증)
   │
페이즈 3 ─ 실행환경   (3~6개월) 스케줄 + IPC + 능력 토큰
   │
페이즈 4 ─ 저장       (3~6개월) 파일시스템 + 영속 체크포인트
   │
페이즈 5 ─ 셸과 자체호스팅 (3~6개월) 글 셸 + 에디터 + 컴파일러 포팅
   │
   ▼
MVP: 글 OS 안에서 글 컴파일러 빌드 가능
```

총 **19~33개월**. 풀타임 솔로 가정 1.5~2.5년.

### 단계 의존성 그래프

```
페이즈 0 ─┬─→ 페이즈 1 ─→ 페이즈 2 ─┬─→ 페이즈 3 ─→ 페이즈 5
          │                          │
          └─→ (병행 가능)            └─→ 페이즈 4 ─→ 페이즈 5
```

- 페이즈 4(저장)는 페이즈 3(IPC)과 부분 병행 가능 — 영속 체크포인트가 IPC 구조에 의존하지만, FS 인터페이스 설계는 독립 시작 가능
- 페이즈 5는 페이즈 3+4 모두 필요

## 2. 각 단계 한 문단 요약

> 상세는 `docs/phases/<N>-*.md`

### 페이즈 0 — 준비

**목표**: 글 컴파일러에 OS 모드(freestanding, 인라인 asm, 섹션 속성, Multiboot2 ELF 출력)를 추가하고, QEMU+GDB 디버깅 워크플로를 셋업한다. **글 컴파일러 자체호스팅 고정점은 유지되어야 한다** (회귀 없음).

**통과 조건**: 글 소스 한 줄 `[커널진입]은 { (* 빈 무한루프 *) (1)동안 { } }` 가 freestanding ELF로 빌드되고, GRUB 또는 자체 부트로더로 QEMU에 부팅되어 명령 0에서 정지 (확인은 GDB로).

### 페이즈 1 — 부팅과 콘솔

**목표**: long mode 진입, 최소 GDT/IDT, VGA 텍스트 출력, 인터럽트 기반 PS/2 키보드 입력. **글 코드로 한글 에코 동작**.

**통과 조건**: QEMU에서 부팅 → "안녕하세요" 자동 출력 → 키 입력 받아 화면에 에코 (특수키 무시, ASCII+한글 일부 가능).

### 페이즈 2 — 메모리와 격리 (★ 핵심)

**목표**: 물리 프레임 할당기, 가상 메모리 페이지 테이블, 힙. **그리고 두 개의 SIP가 같은 주소공간에서 격리 동작**을 시연 — 한 SIP가 의도적으로 잘못된 메모리 접근을 시도해도 컴파일 자체가 실패하거나 런타임 트랩으로 잡힘.

**통과 조건**:
- 페이지 할당기/매퍼 동작 (4KB·2MB 페이지)
- 두 SIP가 빌드되고 framekernel이 로드해서 실행
- **SIP A가 SIP B 메모리를 침범하려는 글 코드가 컴파일 타임 또는 정의된 런타임 오류로 잡힘**

**spike 우선순위 1**: 결정 A(소프트웨어 격리) 검증. 글 컴파일러가 임의 메모리 접근을 막을 수 있는가? 막을 수 없으면 폴백 (페이지 테이블 격리)으로 전환.

### 페이즈 3 — 스케줄·IPC·능력

**목표**: 협력적 → 선점적 스케줄러, 동기 메시지 IPC, 능력 토큰 발급/회수 메커니즘.

**통과 조건**:
- 3개 이상 SIP가 라운드로빈으로 시간 분할 실행
- SIP 간 메시지 1만 회/초 이상 가능 (단일 코어 가정)
- 파일 능력 없는 SIP가 파일 접근 시도 시 거부됨

### 페이즈 4 — 저장과 영속

**목표**: 디스크 드라이버, 파일시스템(자체 또는 FAT32), SIP 상태 체크포인트.

**통과 조건**:
- 파일 읽기/쓰기 동작
- 임의 SIP의 상태가 30초 간격 자동 체크포인트
- 재부팅 후 SIP가 마지막 체크포인트에서 자동 재개

### 페이즈 5 — 셸과 자체호스팅

**목표**: 글 언어를 직접 입력받는 셸, 라인 에디터, 글 컴파일러를 글 OS 위에서 실행.

**통과 조건 (★ MVP)**:
- 글 셸에서 `편집 hello.gl` 로 에디터 진입, 글 코드 입력, 저장
- 셸에서 `빌드 hello.gl` 로 컴파일, `실행 hello` 로 결과 확인
- **결정적 통과**: 글 컴파일러 소스 트리(`src/*.gl`)를 글 OS에 올려서 컴파일러 자체를 빌드. 결과 바이너리가 동일 소스를 다시 빌드 가능 (글 OS 위의 자체호스팅 고정점)

## 3. 단계 전환 의식 (Phase Gate Ritual)

각 페이즈가 끝날 때 다음을 진행한다. 안 하고 넘어가는 페이즈는 6개월 뒤 돌아오게 됨.

### 3-1. 통과 조건 체크리스트
- [ ] 페이즈 문서의 통과 조건 모두 객관적으로 확인됨 (스크린샷·로그·테스트 결과 보존)
- [ ] 자체호스팅 컴파일러 (글 본가) 고정점 유지 (회귀 없음)
- [ ] main 브랜치가 빌드 + 부팅 가능 상태

### 3-2. 회고 한 페이지
페이즈 문서 끝에 다음 4개 항목으로 작성:

1. **달성한 것** — 통과 조건 + 보너스
2. **놓친 것** — 처음 계획에 있었으나 안 됐고, 다음 페이즈로 이월된 것
3. **발견한 막다른 길** — 시도했다 폐기한 접근 (다음 사람이 같은 실패 반복 안 하게)
4. **다음 페이즈로의 spike 우선순위** — 가장 불확실한 가정 3개

### 3-3. 결정 기록 갱신
이번 페이즈에서 한 큰 결정을 §4에 한 줄씩 추가.

### 3-4. 위험 등록부 갱신
`04-위험과대응.md`의 위험 항목 중 이번 페이즈에서 해결된 것 / 새로 드러난 것 갱신.

## 5. 알려진 막다른 길 (사전 인지)

페이즈 작업 중 부딪힐 가능성 높은 막힘들. 발생 신호를 알면 대응이 빨라진다.

### 5-1. 페이즈 0: 컴파일러 자체호스팅 회귀
- **신호**: stage2 ≠ stage3 SHA, 또는 빌드 실패
- **대응**: `bootstrap/src/*.c` (C 부트스트랩) 부활. **페이즈 0 첫 주에 빌드 가능 상태 확보 권장** (보험)

### 5-2. 페이즈 1: 한글 식별자 ↔ 조사 형태소 충돌
- **신호**: `타이머인터럽트` 같은 식별자에서 렉서 세그폴트
- **대응**: 페이즈 0의 1주차 작업(렉서 문맥화)이 충분치 않았다는 신호. 페이즈 0으로 잠시 복귀

### 5-3. 페이즈 2: 컴파일러 격리 보증 부족 (★ 가장 큰 위험)
- **신호**: 글 코드로 다른 SIP 메모리를 침범할 수 있는 코드가 컴파일 통과
- **대응**: 결정 A 폴백 → 페이지 테이블 격리. **결정 C도 자동 폴백** (분리 주소공간). 페이즈 2 후반부 재계획

### 5-4. 페이즈 3: IPC 성능 너무 낮음
- **신호**: 메시지 1만 회/초 미달
- **대응**: 단일 주소공간이라 메모리 복사 0이어야 하는데 어디선가 복사 발생. spike로 핫스팟 찾기 — 캐시 라인 정렬, false sharing, MMU 오버헤드

### 5-5. 페이즈 4: 영속 체크포인트 비용 폭발
- **신호**: 100MB SIP의 30초 간격 체크포인트가 1초 넘게 걸림
- **대응**: 결정 D 폴백 → 명시적 저장 모델. 또는 점진적 체크포인트(dirty page 추적)로 우회

### 5-6. 페이즈 5: 컴파일러 포팅이 OS API 가정 불일치
- **신호**: 글 컴파일러가 `fopen`/`fread`/`printf`/`malloc` 호출, 글 OS는 다른 API
- **대응**: 컴파일러 측에 plug-in 점 만들기 (글 표준 라이브러리 추상 인터페이스). **이 작업은 페이즈 4 후반부터 미리 시작** (충돌 방지)

### 5-7. 일반: 풀타임 번아웃
- **신호**: 2주 이상 진척 없음, 새 작업 시작 동기 부재
- **대응**: 페이즈 일정 멈춤 선언. 강제 휴식 1~2주. 라이프 워크로 진행하려면 휴식도 일정에 포함되어야 한다

## 6. 페이즈 간 병행 작업 가능 영역

페이즈가 순차로만 보이지만, 일부 작업은 다음 페이즈 spike와 병행 가능. 시간을 아끼는 게 아니라 **다음 페이즈의 불확실성을 미리 검증**하는 용도.

| 현재 페이즈 | 다음 페이즈를 위한 병행 작업 |
|---|---|
| 페이즈 0 후반 | 페이즈 1 spike: VGA 텍스트 출력 글 코드 한 줄 |
| 페이즈 1 후반 | 페이즈 2 spike: 컴파일러가 임의 메모리 접근 막을 수 있나? (실제 OS 코드 없이도 검증 가능) |
| 페이즈 2 후반 | 페이즈 3 spike: 메시지 패싱 설계서 작성 |
| 페이즈 3 후반 | 페이즈 4 spike + 페이즈 5 spike(컴파일러 plug-in 점) |

## 7. 폐기 기준 (Kill Criteria) — 프로젝트 자체 중단 조건

작품 의식과는 별도로, 다음 중 둘 이상 동시 발생 시 프로젝트 자체를 재정의한다 (중단 또는 범위 대폭 축소):

1. **컴파일러 격리 (결정 A) 폴백 + 단일 주소공간 (결정 C) 폴백** 동시 발생 → 글 OS의 차별점이 거의 사라짐
2. **렉서 식별자 문제가 페이즈 1 이후에도 반복 발견** → 글 언어 자체 재설계 필요
3. **18개월 진행 후 페이즈 2 통과 못함** → 시간 안배 재검토
4. **풀타임 가용성이 6개월 이상 끊김** → 파트타임 모드로 재계획 (일정 ×3)
