# 아키텍처 비전

연구조사(`01-연구조사.md`)에서 살펴본 옵션 중 **무엇을 채택하고, 무엇을 거르고, 무엇을 보류했는가**. 모든 결정은 **폐기 시 폴백**과 함께 기록한다.

이 문서는 의사결정 기록이지 구현 명세가 아니다. 구체 구현은 페이즈 문서에서 한다.

---

## 채택 결정 5건

### 결정 A — 소프트웨어 격리 (Singularity/Theseus 식) ★ 정체성

**선택**: 프로세스 격리의 1차 보증을 글 컴파일러의 타입·메모리 안전성에 둔다. MMU 페이지 테이블은 보조 (디버깅·메모리 레이아웃·하드웨어 보호의 마지막 선).

**근거**:
- 글 컴파일러를 직접 통제하므로 isolation 가정을 컴파일러에 내장 가능
- 컨텍스트 스위치가 함수 호출 수준 → IPC 비용 극소화 (글 OS의 통신 모델은 IPC 중심)
- C/C++ 같은 unsafe 언어 지원 의무 없음 (글 단일)
- **이것이 글 OS의 가장 강력한 차별화 요소** — 정체성

**폐기 시 폴백 (Plan B)**:
- 글 컴파일러의 안전성 보증이 불충분/검증 불가로 판명되면 → 전통적 페이지 테이블 격리로 전환
- 전환 시 단일 주소공간 결정(C)도 동시에 폐기 (둘은 묶임)
- 이 폴백은 **페이즈 2의 spike에서 결정**된다

**검증 시점**: 페이즈 2의 spike 1주차 — 글 컴파일러가 임의 메모리 접근을 컴파일 타임에 막을 수 있는지 (배열 경계, 포인터 캐스트, 산술)

---

### 결정 B — 능력 기반 보안 (seL4/KeyKOS 식) ★ 정체성

**선택**: 모든 자원(파일·메모리·디바이스·다른 SIP)에 대한 접근은 **능력 토큰**으로만. 사용자 ID/그룹 ID 등의 ambient authority는 도입하지 않는다.

**근거**:
- POSIX 권한 누더기를 안 들고 오는 가장 깨끗한 방법
- 권한 상승 공격이 구조적으로 불가능
- 글 1급 타입으로 표현하면 SOV 어순과 자연스럽게 결합: `이파일을 읽기능력으로 열기.`
- 결정 A와 시너지: 컴파일러가 능력 누출도 컴파일 타임에 막을 수 있음

**폐기 시 폴백**:
- 능력 모델의 복잡도가 폭발하면 → ACL 기반으로 후퇴
- 단, ACL을 도입할 거면 글 OS의 보안 모델 차별점이 거의 사라짐. **마지막 폴백**

**검증 시점**: 페이즈 3 spike — 능력 모델의 일상 API 사용성 검증

---

### 결정 C — 단일 주소공간 ★

**선택**: 64비트 주소공간 하나에 모든 SIP 공존. 각 SIP는 자기 영역만 접근 가능 (결정 A로 보장). IPC = 포인터 전달.

**근거**:
- 결정 A의 자연스러운 귀결 — 페이지 테이블 격리가 없다면 주소공간 분리 의미 없음
- IPC가 메모리 복사 없이 가능 → 성능 결정적 우위
- TLB flush 사실상 없음

**폐기 시 폴백**:
- 결정 A가 폴백되면 자동으로 폴백 (전통적 분리 주소공간)

**검증 시점**: 페이즈 2 spike와 묶임

---

### 결정 D — 영속 메모리 모델 (KeyKOS 식)

**선택**: SIP 상태는 자동으로 디스크에 영속화. 종료/재부팅이 사용자에게 안 보임. 명시적 저장은 디버깅 도구로만 존재.

**근거**:
- 사용자 경험 차별화가 큼
- 현대 NVMe/PMEM 하드웨어와 잘 맞음
- "글 에디터에서 작업하다 전원 끄고 다음에 그대로 재개"

**폐기 시 폴백**:
- 체크포인트 비용이 과하면 → 명시적 저장 모델로 후퇴
- 후퇴해도 글 OS의 정체성은 유지됨 (결정 A·B만큼 핵심은 아님)

**검증 시점**: 페이즈 4 spike — 100MB SIP 상태 체크포인트 비용 측정

---

### 결정 E — 통일된 IPC = 동기 메시지 패싱 (L4 식)

**선택**: IPC는 동기 메시지 한 메커니즘으로 통일. 파이프·소켓·시그널·세마포어 등의 분기 없음.

**근거**:
- L4가 동기 메시지의 함수 호출급 성능 입증
- 결정 C(단일 주소공간) 위에서는 메시지가 포인터+능력 토큰 전달로 압축됨
- 글 SOV 어순과 자연 매핑: `"안녕"을 화면SIP에 보내기.`

**폐기 시 폴백**:
- 비동기 패턴이 필수로 드러나면 → 큐 기반 비동기 추가 (이중 메커니즘 허용)
- 그래도 시그널·세마포어 같은 옛 모델은 도입 안 함

**검증 시점**: 페이즈 3 — 첫 두 SIP 간 통신 구현 시점

## 채택하지 않은 옵션

### Plan 9 식 전체 통일 ("모든 것은 파일")

- **이유**: 도그마틱. 디바이스·프로세스·메모리까지 파일로 보면 추상화 비용 누적
- **부분 채택**: 파일시스템 인터페이스의 통일성 정신만 (페이즈 4)

### 형식 검증 (seL4 식)

- **이유**: 풀타임 솔로로 형식 증명까지는 비현실적. 5년 단위 추가 작업
- **대안**: 회귀 테스트 + 모델 기반 테스트로 신뢰 확보. 형식 검증은 **5년 후 야망**으로 보류

### 마이크로커널 vs 모노리식 — 결정 보류

- 결정 A 채택 시 이 구분이 흐려짐 (모든 SIP가 같은 주소공간, 격리는 컴파일러)
- **잠정**: "framekernel" — 작은 커널 코어 + 나머지 SIP. 페이즈 2 spike 결과로 확정

### Unikernel / 라이브러리 OS

- **이유**: 글 OS는 멀티 SIP가 핵심. 단일 애플리케이션 = OS 모델은 부적합

### POSIX 부분 호환 (Redox 식)

- **이유**: 비-목표. `00-비전과원칙.md` 3절 참조

### 멀티 사용자

- **이유**: 능력 모델은 사용자 개념을 필요로 하지 않음. 1인용 작품

## 보류한 결정 (페이즈가 진행되며 답을 정함)

| 항목 | 보류 사유 | 결정 시점 |
|---|---|---|
| **부트로더**: GRUB vs 자체 작성 | 자체 작성이 작품성 있지만 페이즈 0 비용 증가 | 페이즈 0 시작 시 |
| **파일시스템**: 자체 vs FAT32 호환 | FAT32는 외부 도구 호환 ↑, 자체는 작품성 ↑ | 페이즈 4 spike |
| **드라이버 모델**: 정적 링크 vs 동적 로드 | 정적이 단순, 동적은 라이브 진화 가능 (Theseus) | 페이즈 2 후반 |
| **GUI 도입 여부** | MVP에는 텍스트로 충분. 페이즈 5에서 결정 | 페이즈 5 시작 시 |
| **네트워킹** | 비-목표지만 매우 후기에 가능성 검토 | MVP 달성 후 |
| **멀티프로세서(SMP) 지원** | 단일 코어로 MVP. SMP는 페이즈 3 이후 | 페이즈 3 후반 |
| **그래픽 출력**: VGA 텍스트 → VESA 프레임버퍼 전환 시점 | VGA로 페이즈 1~3 진행 후 결정 | 페이즈 3 후반 |

## 아키텍처 한 페이지 요약 (cheat sheet)

```
┌─────────────────────────────────────────────────────┐
│                  글 OS                              │
│                                                     │
│  사용자 SIP들 (모두 글로 작성)                       │
│  ┌────────┐  ┌────────┐  ┌────────┐  ┌──────────┐  │
│  │ 셸     │  │ 에디터 │  │ 컴파일러│  │ 파일관리 │  │
│  └────────┘  └────────┘  └────────┘  └──────────┘  │
│       ↑          ↑          ↑           ↑          │
│       └──────────┴────[메시지+능력]─────┘          │
│                       │                             │
│  ┌──────────────────────────────────────────────┐  │
│  │  framekernel (글 + 인라인 asm 최소)           │  │
│  │  - 부팅, 페이지 매핑, IDT, 타이머             │  │
│  │  - SIP 로더, 메시지 라우터                    │  │
│  │  - 능력 발급/회수, 영속 체크포인터            │  │
│  └──────────────────────────────────────────────┘  │
│       │ 인라인 asm (cli/sti/in/out/lgdt/lidt 등)   │
│  ┌──────────────────────────────────────────────┐  │
│  │  하드웨어 (x86-64, QEMU 또는 실기)            │  │
│  └──────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────┘
```

**격리는 컴파일러로** (결정 A) → 모든 SIP가 같은 주소공간 (결정 C) → 메시지 = 포인터+능력 (결정 B, E) → 상태는 영속 (결정 D)

이 다섯이 한 묶음이다. 한 결정이 폴백하면 다음 결정도 검토 대상이 된다.
